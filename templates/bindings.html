How do I know a device provisioned successfully?
A device is considered successfully provisioned when, after ZTP, it boots into the delivered config and is reachable at its management IP. This page reports it in layers:
  • DHCP lease — the server saw the device and leased it an IP (it reached ZTP at all).
  • Ping — the device answers ICMP at its assigned IP (booted, network up).
  • SSH — TCP/22 is open (management plane up, config applied far enough to allow SSH).
  • VERIFIED — we logged in over SSH and the device's host-name matches the expected hostname → the correct config landed on the correct device. Requires SSH credentials (set Default or per-device on the Dashboard).
Health check targets the Management IP (post-ZTP) if set — this is usually a different subnet than the DHCP range (the device's real mgmt/loopback after the full config loads), and devices may span many subnets. The ZTP server (or wherever this app runs) must have an L3 route to those subnets for ping/SSH to succeed. If no Mgmt IP is set, it falls back to the DHCP IP. The “checked <ip>” line shows which IP was actually probed.
